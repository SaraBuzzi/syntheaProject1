# SQL Query Fragmentation and Translation

A thesis project exploring SQL query translation and execution in a fragmented database environment.

## Overview

The goal of this project is to simulate query execution on a fragmented database, studying how SQL queries can be translated and how the resulting execution plans can be analyzed.

The practical work focuses on different types of SQL queries, investigating how filtering, grouping, and aggregate conditions interact with database fragmentation.

The database is populated with synthetic healthcare data generated using Synthea.

## Project Structure

- **`/output`** — Source datasets used to populate the database.
- **`/sql`** — SQL scripts for table creation, data insertion, and fragment definition.
- **Python notebooks** — Interactive experiments and tests for query translation and execution.

Query translation is explored through three main categories, each implemented in a dedicated notebook:

- **Query 1:** `SELECT ... FROM ... WHERE ...`
- **Query 2:** `SELECT ... FROM ... GROUP BY ...`
- **Query 2W:** `SELECT ... FROM ... WHERE ... GROUP BY ...`
- **Query 3:** `SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ...`

## Technologies

- **PostgreSQL** — Database management and SQL query execution
- **Python 3.13** — Query translation logic and experimental testing
- **Jupyter notebooks** — Interactive development and experimentation
- **PyCharm** — Development environment

## Implementation

The project combines SQL scripts and Python code to explore query translation in a fragmented database.

- Database fragments are managed through dedicated SQL scripts and views.
- Python notebooks implement and test the translation of different query structures.
- Execution plans are printed and inspected to help verify the behavior of translated queries.

## Data Source

The project uses synthetic healthcare datasets generated by **Synthea**, an open-source synthetic patient generator.
